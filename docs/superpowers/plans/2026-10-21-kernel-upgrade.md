## Review Focus
1. DNS 语义：`dns-remote` 必须 `detour: <业务出口>`；`dns-direct` / `dns-local` 绝不写指向空 direct 的 `detour`（`CheckConfig` 放行、`Start` 拒绝）；**DNS 服务器自己的域名只由 IP-only 的 `dns-bootstrap` 解析，构建器有依赖环检查，直连 DNS 配成域名 DoH 的真查询能完成**；`route.default_domain_resolver` 齐全。
2. 闸门是否真的在拦：黄金文件 + 原始配置不变量 + 适配副本 `CheckConfig` + 真启动 + 真流量；故意改坏一条规则能被至少一道闸抓住（每个构建器任务都要演示一次反例）；原始配置与主机适配副本的断言分开，适配差异受白名单约束。
3. 线格式与类型逐通道：分组是 `String`、统计是 `Map`，经**真实 codec 信封**（统计 `JSONMethodCodec`、分组默认 Standard codec）穿过 `BinaryMessenger` 的 Kotlin → Dart 往返证明 Dart 得到非零 `BoxStats` / 非空分组，不手工构造 Map；`OutboundSnapshotTest` 现有断言迁移后仍成立；`FailureCode` 映射不变（`create-service:` / `start-service:` 前缀）。
4. Kotlin：取消检查点与回收完整（`KernelStartSequenceTest`、`CoordinatorCoreTest` 不改断言通过，另加「取消在每个检查点 / startEngine 返回后」与「teardown 逐步抛错」的新用例）；`teardown(soft/hard)` 不遗漏 Seq 引用 / tun fd / 网络监听；不承诺「启动中取消立即返回」（协调器只置位，见 spec §4.2）。
5. 回滚面：旧 aar、旧脚本、旧 Release tag 仍可用；新旧订阅文件互相的可读性（§8.2）。
6. 功能缺口一律隐藏而不是保留假开关；存档值不丢；`clash_api` 永不生成。
7. WARP 出站图：两种模式下 `warp` 都不是 `select` / `auto` 成员；图单元测试 + 真流量测试同时存在。
8. 端点贯通：Dart 里所有只读 `outbounds` 的消费者都认 `endpoints`，且按用途选对视图（叶子视图用于计数与候选，完整集合用于分组、类型索引与引用重写）；端点独占 / 混合 / 端点带默认标记 / 分组含 auto + 端点 + 隐藏节点引用四种形态有端到端测试。
