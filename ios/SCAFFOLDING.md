# iOS Scaffolding – manual steps in Xcode

This document tracks the bits that **cannot** be generated by editing files
on disk. After the Swift sources land you still need to wire them up in
the Xcode project (`ios/Runner.xcodeproj`) and create the network
extension target. Follow the checklist below from top to bottom.

## 1. Add the SingBoxPacketTunnel target

1. Open `ios/Runner.xcworkspace` in Xcode.
2. **File → New → Target…**
3. Choose **iOS → Application Extension → Network Extension**.
4. Configure:
   - Product Name: `SingBoxPacketTunnel`
   - Language: Swift
   - Embed in Application: `Runner`
   - Bundle Identifier (auto-derived): `com.clashmiao.clashmiao.SingBoxPacketTunnel`
     - This must end with `.SingBoxPacketTunnel` because Runner's
       `TunnelManager` derives the provider bundle id by appending
       that suffix to `BASE_BUNDLE_IDENTIFIER`.
5. When prompted "Activate scheme?", choose **Activate**.
6. Xcode generates a stub `PacketTunnelProvider.swift` and Info.plist
   inside `ios/SingBoxPacketTunnel/`. **Delete the stub Swift file**;
   our scaffold already provides `ClashMiaoTunnelProvider.swift` etc.
   Move/replace the Info.plist with the one already on disk at
   `ios/SingBoxPacketTunnel/Info.plist`.
7. In the project navigator, drag the existing files into the new
   target so they actually compile:
   - `ios/SingBoxPacketTunnel/ClashMiaoTunnelProvider.swift`
   - `ios/SingBoxPacketTunnel/TunnelLogger.swift`
   - `ios/SingBoxPacketTunnel/TrafficStats.swift`
   - `ios/SingBoxPacketTunnel/Kernel/*.swift`
   - `ios/Shared/*.swift` (shared between Runner and the extension –
     add to **both** target memberships)
8. In the extension's **Info.plist**, confirm:
   ```
   NSExtension → NSExtensionPrincipalClass = $(PRODUCT_MODULE_NAME).ClashMiaoTunnelProvider
   ```

## 2. Capabilities & entitlements

Both Runner and SingBoxPacketTunnel need:

- **Network Extensions** capability with the `Packet Tunnel` flavour.
- **App Groups** capability with `group.com.clashmiao.shared` (or
  whatever value you used for `BASE_BUNDLE_IDENTIFIER` in
  `Base.xcconfig`).

Steps:

1. Select the **Runner** target → Signing & Capabilities.
2. `+ Capability → Network Extensions` (tick `Packet Tunnel`).
3. `+ Capability → App Groups` → add `group.com.clashmiao.shared`.
4. Repeat for the **SingBoxPacketTunnel** target.
5. Xcode will update `Runner.entitlements` / `SingBoxPacketTunnel.entitlements`
   – verify they match the files on disk (this scaffold ships ready-made
   plists you can keep using).

## 3. Hook up `Base.xcconfig`

1. Select the **Runner** project (top of project navigator).
2. Under the **Info** tab → **Configurations**, set the
   "Based on Configuration File" for *Debug*, *Profile*, and *Release*
   on both **Runner** and **SingBoxPacketTunnel** targets to point at
   `Base.xcconfig`.
3. Edit `ios/Base.xcconfig` if you need to override
   `DEVELOPMENT_TEAM` for CI signing.

## 4. Link libcore.xcframework

> **Heads-up:** the repo currently ships a placeholder
> `ios/Frameworks/Libbox.xcframework` (vanilla sing-box, no `Mobile*`
> wrapper). The Swift sources in this scaffold import the
> `Libcore` module and call `MobileSetup` / `MobileParse` /
> `MobileBuildConfig` / `MobileGenerateWarpConfig`. These do **not**
> exist in the current placeholder framework – the scaffold will not
> compile until you replace it with the real artefact.

Once `core/build.sh ios` has produced `ios/Frameworks/Libcore.xcframework`:

1. Select the **Runner** target → **General → Frameworks, Libraries,
   and Embedded Content** → drag `Libcore.xcframework` in.
   - Set "Embed" to **Embed & Sign**.
2. Repeat for the **SingBoxPacketTunnel** target.
   - Set "Embed" to **Do Not Embed** – the framework is already embedded
     by Runner and the extension just needs to link against it.

## 5. Re-install pods

After saving the project file:

```
cd ios
pod install
```

The Podfile already declares both targets. The first install after
adding the extension target may emit a warning the first time CocoaPods
sees `SingBoxPacketTunnel`; subsequent runs are quiet.

## 6. Provisioning

For real-device builds, App Store Connect / your provisioning profile
needs:

- **App ID** for `com.clashmiao.clashmiao` with **Network Extensions**
  and **App Groups** enabled.
- **App ID** for `com.clashmiao.clashmiao.SingBoxPacketTunnel` with the
  same two capabilities.
- An **App Group** named `group.com.clashmiao.shared` (matching
  `BASE_BUNDLE_IDENTIFIER`) registered under Identifiers → App Groups,
  and ticked on **both** App IDs above.

Pure simulator runs work without any of this, but the VPN itself does
*not* function on the simulator (the OS will report a generic
"Permission denied" / state stays `.invalid`). Always test connections
on a real device.

## 7. Adding Swift files to the Xcode project

The project uses `objectVersion = 54` (no folder-synchronised groups), so a new `.swift` file on disk
is **not** compiled until it is registered. Add it to the `MANIFEST` in `ios/scripts/sync_sources.rb`
(path relative to `ios/`, plus the targets it belongs to) and run:

```
GEM_HOME=/opt/homebrew/Cellar/cocoapods/<version>/libexec ruby ios/scripts/sync_sources.rb
```

The script is idempotent. Test files are compiled only into `RunnerTests`, which reaches the app's
symbols through `TEST_HOST` + `@testable import Runner`; do not also add app sources to the test target
(duplicate symbols). Files shared with the extension (`ios/Shared/Kernel/*`) go into both `Runner` and
`SingBoxPacketTunnel`.

## 8. Unit tests

```
cd ios
xcodebuild test -workspace Runner.xcworkspace -scheme Runner \
  -destination 'platform=iOS Simulator,name=iPhone 17' -only-testing:RunnerTests \
  CODE_SIGN_IDENTITY=- CODE_SIGNING_REQUIRED=NO
```

Use ad-hoc signing, **not** `CODE_SIGNING_ALLOWED=NO`: the host app resolves the App Group container on
launch, and an unsigned simulator build has no entitlements, so the host aborts and the test run hangs.
Boot the simulator first (`xcrun simctl boot <id>`) if `xcodebuild` sits idle after "Resolve Package Graph".

## 9. Smoke test (real device)

The VPN does not work in the simulator. On a real iPhone:

1. Run Runner. `initialize` loads the VPN preference and, on first run, iOS shows "Add VPN Configurations".
2. Import a subscription and tap connect. The kernel snapshot (`com.clashmiao.app/kernel.snapshot`)
   should go `stopped → starting → started`; the egress IP should change.
3. Check `docs/superpowers/research/2026-10-20-ios-device-smoke.md` for the full list (background /
   foreground, kill and relaunch, toggling the VPN in system Settings, Wi-Fi ↔ cellular, memory headroom).

Diagnostics: every snapshot is logged as `snapshot epoch=… version=… status=… attempt=… desired=… source=…`;
the extension logs `memory <stage>: available=… KB` at lifecycle steps and writes the lowest observed
headroom into `extension-state.json`.
