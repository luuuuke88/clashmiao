# 国内直连清单的排除表——生成 lib/domain/config/data/cn_direct_rules.dart 时
# 由 gen_cn_direct_rules.dart 读取并应用，是生成管线的一部分，不是事后手改。
#
# ## 为什么要排除
#
# geosite-cn 里带着一批谷歌系域名（上游域名数据里打了 `google@cn` 标签的
# 那部分）：当年谷歌在北京有缓存节点（GOOGLECN），这些域名
# 在大陆可以直连。这个前提早已不成立——2026-10 在西安移动真机上实测，
# www.gstatic.com / connectivitycheck.gstatic.com / fonts.gstatic.com /
# csi.gstatic.com / www.google.cn 走直连全部约 5.4 s 超时（000）。后果是智能
# 模式下，引用谷歌字体或静态资源的网站在大陆网络下卡住。
#
# 排除之后这些域名不再命中直连规则，落到最终出站（代理），DNS 也随之走远端。
#
# ## 格式
#
# - 一行一条，`#` 之后是注释，空行忽略。
# - 含 `/` 的是 CIDR：清单里被它覆盖的网段删掉，覆盖它的更大网段会被拆开、
#   只挖掉这一段。
# - 其余是域名：该域名本身及其所有子域，在精确清单（cnDirectDomains）和后缀
#   清单（cnDirectDomainSuffixes）里都删掉。
# - 如果某条保留下来的更宽的后缀（典型是顶级域 `cn`）仍会盖住被排除的域名，
#   生成器会把那条后缀改写成一条"后缀匹配、但跳过被排除域名"的正则
#   （cnDirectDomainRegexes），保证被排除的域名真的落到代理。
#
# ## 维护
#
# 规则库升级后，跑一次生成器即可自动重新应用这份表；测试
# test/domain/config/data/cn_direct_rules_test.dart 会用一组谷歌系关键词兜底，
# 新数据里冒出这份表没覆盖到的谷歌域名会直接让测试失败，届时把它补进来。
